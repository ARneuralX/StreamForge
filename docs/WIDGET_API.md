# StreamForge Widget API

Widgets are ES modules at `widgets/<id>/index.js` and export a default object with `meta` and `mount(api)`.

```js
export default {
  meta: { title: "Example", description: "A small overlay", width: 420, height: 180, x: 0, y: 0, anchor: "top-left" },
  mount(api) {
    api.on("chat", (event) => { /* use validated event data */ });
    api.root.textContent = "Ready";
  },
};
```

The host supplies `root`, `on(event, handler)`, `sound`, timer helpers, per-widget `storage`, and `theme`. Supported events are `chat`, `follow`, `sub`, `raid` and `redeem`. `sound.play(cue)` uses a short synthesized WebAudio tone; browsers may require an earlier user interaction before audio plays. The API is intentionally small. Widgets run in sandboxed frames with network access blocked by CSP. Treat every event value as untrusted text and render it with DOM text APIs.

Optional safety and motion members are `api.safeMode` (`off`, `reduced` or `minimal`) and `api.motionScale` (1, 0.5 or 0.15). A widget may listen for `api.on("safeMode", ({level, motionScale}) => ...)` to update its own motion. These preferences reduce motion; they do not guarantee medical or accessibility outcomes. Safe Mode can be set in the dashboard, by a moderator `!safe-mode <off|reduced|minimal>` command, or overridden for an overlay source with `?safeMode=minimal`.

`api.theme` provides the current validated tokens: `accent`, `accent2`, `background`, `text`, `glow` (six-digit hex colors), `radius` (0–40), `fontStack` (`system-ui`, `Arial`, `Georgia` or `Trebuchet MS`) and `animationSpeed` (0.5–2). The host applies matching CSS custom properties to the frame root and sends updates without remounting widgets. Widgets that do not read these tokens remain compatible. Theme changes come from five presets, the moderator `!theme <Halloween|Neon|Cozy|Retro|Clean>` command, or a one-click Overlay Kit. AI theme requests use a named preset fallback while Codex is unavailable; no generated code is accepted as a theme.

`api.storage.get(key)` and `api.storage.set(key, jsonValue)` provide small per-widget JSON state. The sandbox sends storage requests to its host over `postMessage`; only the host talks to the local storage API. Keys are limited to 40 safe characters and values to 8 KB. Keep stored data non-sensitive and validate it again when read.

Optional `api.emit("moment", {kind, label})` reports a widget moment to the host. Only the fixed kinds `natural20` and `goalReached` are accepted; arbitrary labels and other free-form data are ignored. The host verifies the message came from the matching sandboxed widget and rate-limits each widget. A moment does not mean a clip was created; see [Auto-Clips](AUTO_CLIPS.md) for the Twitch authorization and live-state requirements.

The Widget Passport is generated by the server from source, metadata and current scan results. It lists statically detected event/API use and a heuristic motion-risk level. It is informational and cannot certify widget behavior. Imported `.sfwidget` passport content is never trusted; the server recomputes it.

`api.hype` is a read-only aggregate snapshot with a 0–100 `value`, `level` (`calm`, `warm`, `hot`, `peak`), `trend` (`rising`, `steady`, `falling`), rolling 10/60 second message rates and unique-chatter counts, emote density, command rate and aggregate event boosts. `api.on("hype", snapshot => ...)` receives server updates at no more than four per second. The engine uses short-lived salted identifiers in memory to count unique chatters; snapshots and persisted settings contain no names or message text. Sensitivity, manual boost, mute and reactive-widget settings are available in the Overview Hype meter. Its separate simulated-energy slider is labeled SIMULATED and expires after 15 seconds.

Viewer build requests are normalized with Unicode NFKC, control/bidi cleanup and whitespace collapse before the 300-code-point limit and blocklist check. Request cards show a heuristic script chip (Latin, Bengali, Arabic, Cyrillic, CJK or Japanese). With “Require manual approval for non-English viewer requests” enabled (default), non-English requests stay queued until a moderator approves them, including when vote or timed auto-build is selected. Script detection and English identification are dependency-free heuristics and can be imperfect. Request text remains untrusted data and is rendered as text.
